02  —  How it works

The life of a request, in seven quiet steps.

01

Authenticate

A virtual key tells the gateway which client organisation is calling. Unknown or revoked keys never get further.

02

Check the budget

Per-client caps and spike detection run before a single token is spent. Runaway agents are stopped, not discovered.

03

Mask personal data

Presidio with UK detectors swaps names, NHS and NI numbers and postcodes for typed placeholders.

04

Look in the cache

Exact match by default, semantic match when a client opts in. Every entry is masked and isolated per client.

05

Route wisely

The requested model first, then retries and backup models. Requests that can wait go to batch APIs at a lower price.

06

Restore

Real values return to the answer, in streamed chunks and inside tool calls, with JSON kept perfectly valid.

07

Write the ledger

Cost, savings and metadata are recorded. The prompt text never is. Every figure can be traced and reconciled.

03  —  Privacy first

Personal data never leaves your side.

Masking runs inside the gateway, before the cache and before any provider. Logs hold metadata only. If the privacy layer ever fails, the request is refused, even for fail-open clients.

  • NHS numbers checked with Modulus 11
  • NI numbers and UK postcodes detected
  • Fake-PII leak test across cache, database and logs
  • Metadata-only audit log, never prompt text

04  —  What sets it apart

Six features. One clear bill.

Caching

Exact and semantic cache

Stored masked, isolated per client. Prompts with NHS or NI numbers use exact match only.

Ledger

Savings ledger

Versioned price table, list-price baseline, provider discounts excluded.

Batch

Batch Autopilot

Requests that can wait go to provider batch APIs, saving is recorded automatically.

Insight

Cache Doctor

Finds the timestamps, IDs and reordering that quietly break your cache.

Guard

Runaway Agent Guard

Spend caps and spike alerts per client and per key, with an optional hard stop.

Resilience

Fail-closed by default

Each client chooses fail-open or fail-closed. Either way, masking is never skipped.
